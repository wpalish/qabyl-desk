# QabylDesk 0.1

Оригинальный ограниченный кабинет адресованных синтетических RU/KK пакетов. Reference20 Softr использован только как категория: чужого кода и бренда нет. Администратор публикует неизменную версию и явно выдаёт её указанному аккаунту. Получатель видит только собственные доступные или отмеченные пакеты и один раз сохраняет авторскую ручную отметку.

Кабинет устроен как деловая переписка: собственный список рядом с читаемым текстом, основание и явное действие после содержания. Отметка аккаунта не доказывает чтение, понимание, личность, внешнюю доставку, юридическое ознакомление или электронную подпись.

41 автоматическая проверка:21 предметная/SQLite,9 HTTP,11 controller. Реальные Chrome1126/400CSS, клавиатура, KK, несвязанная правка, отзыв/возврат, сохранение текста при повторном404, запоздалые ответы разных аккаунтов и неполное тело принятого ответа проверены отдельно. [Доказательства](docs/verification.json), [браузерные стадии](docs/browser-proof.json), [UI review и вердикт исправлений](docs/finish-review.json). Это ограниченный локальный процесс, без публичного серверного демо и внешнего security-аудита.

## Локальный запуск

Node24.15–24.x, native ESM/SQLite, без npm-зависимостей. `npm test` запускает весь набор. Для запуска задайте `ADMIN_USERNAME`, `ADMIN_PASSWORD` длиной14–200 символов, `DB_PATH` в закрытой папке, `HOST`, `PORT`, `ORIGIN`; затем `npm start`. По умолчанию сервер слушает127.0.0.1:8859. Пароли и SQLite не включаются в Git. Не помещайте настоящие документы в учебный экземпляр.

## Ограниченный контракт

Черновик содержит1–8 разделов в разных позициях1–20. Публикация требует полных RU/KK заголовков до200 единиц UTF-16 и текстов до5000. Она фиксирует содержание, версию и автора; поздняя правка черновика не меняет старый текст. Предпросмотр привязан к выбранному шаблону, версии содержания и revision области.

Выдача одной публикации одному получателю навсегда уникальна, включая отозванную. Получатель явно сохраняет основание длиной1–2000 единиц UTF-16. Отметка и отзыв конкурируют за один переход1→2. Получатель использует object-version CAS; несвязанная правка администратора не устаревает его форму. Команды администратора используют global-revision CAS. Повтор UUID отказывает, это не idempotent success.

Архив шаблона/публикации закрывает новые выдачи, сохраняя старые снимки. Отзыв доступного пакета закрывает его чтение у получателя. Отмеченный пакет не отзывается. Административный архив убирает terminal-выдачу из рабочего списка; явная история хранит все строки, а получатель сохраняет свою отметку и текст. Нет reopen, reassignment или undo.

При потере ответа запись могла уже состояться: кабинет показывает неизвестный результат и требует явного перечитывания, без автоматической отправки новой команды. На возврате проверяются текущий сеанс и доступ; старые ответы другой сессии игнорируются. В живой вкладке свой несохранённый текст сохраняется отдельно после404. Logout и смена аккаунта очищают его; полная перезагрузка может потерять черновик. No-store и скрытие UI не стирают прежнее знание или копии.

JSON-копия содержит предметную область и историю ключей, без users/auth/audit. Восстановление допустимо только в пустую область с заранее созданными текущими именами/ролями. Проверяются ссылки, снимки, версии, время и однократная привязка ключа к неизменной строке. Это unsigned consistency, не подлинность или исторические права. Полная согласованная SQLite-копия создаётся отдельно. [API](docs/api.md), [правила](PRODUCT.md), [дизайн](DESIGN.md).

Администратор видит всё; одна локальная база и общие лимиты не дают полной изоляции организаций.
